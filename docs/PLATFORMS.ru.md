# Состояние платформ

[English](PLATFORMS.md) · [Разработка](DEVELOPMENT.ru.md)

## Linux

Доступная среда сборки: Debian 13, Linux x86-64 с GCC. Фактические проверки
записаны в [VERIFICATION.ru.md](VERIFICATION.ru.md). Успешная сборка и успешный
запуск — отдельные результаты. Бинарный файл из Debian 13 не считается
автоматически совместимым со старыми версиями glibc.

Tauri 2 подходит для локального Linux-приложения и включает статический экспорт
Next.js. После установки не нужны Node.js, npm или сервер Next.js. Monaco и
его worker, обложки, Markdown уроков, тесты и компилятор поставляются локально.
Для разработки нужны предварительно загруженные зависимости или заполненные
офлайн-кэши.

Системные компоненты Linux:

- WebKitGTK **4.1** и GTK 3. WebKitGTK 4.0 — другое семейство пакетов и не
  удовлетворяет этой сборке.
- C11-компилятор, заголовки libc, binutils, pthread. Runner использует backend
  из системного `/usr`, видимого в изоляции.
- Bubblewrap по пути `/usr/bin/bwrap` и разрешённые user/mount/PID/network
  namespaces. Контейнер или политика системы могут запретить их создание.
- Графическая сессия и поддержка D-Bus/файловых диалогов. Проверка на виртуальном
  экране не заменяет проверку всех desktop portals.

Собственный C++-установщик `.run` устанавливает приложение для одного
пользователя. Debian-пакет объявляет системные зависимости. Ни один из них
не скачивает их скрыто и не содержит целую графическую среду. Для офлайн-установки
совместимые системные пакеты должны быть подготовлены заранее.

## Windows

**В версии 0.1.0 нет проверенной нативной сборки Windows, пути запуска или
установщика Windows.** Кроссплатформенность интерфейса не переносит автоматически
компилятор и runner. Вне Linux исполнение отклоняется, а не запускается без изоляции.

Для настоящего нативного порта Kremen требуются изменения:

| Область | Сейчас | Что нужно для Windows |
| --- | --- | --- |
| Процессы | `fork`, `execvp`, `waitpid`, POSIX-сигналы | `CreateProcessW`, аргументы и кодировки, наследование handles, коды выхода |
| Пути/файлы | `/`, `realpath`, `mkstemp`, `mkdtemp`, `unlink` | UTF-16 Win32, диски/UNC, канонические границы, временные файлы, reparse points |
| Потоки | pthreads, POSIX-runtime | Совместимый pthread backend либо нативная реализация Windows |
| C-backend | GCC C11, pthread, POSIX-заголовки | Согласованный распространяемый комплект и воспроизводимая сборка |
| Изоляция | Linux namespaces/Bubblewrap, rlimits | Отдельная граница доступа, например AppContainer, и управление ресурсами |
| Остановка дерева | Unix-группа и завершение PID namespace | Удержание потомков в Job и завершение; один Job Object не ограничивает доступ к файлам/сети |

Tauri в Windows также требует WebView2. Офлайн-установщик должен проверять
совместимую установленную версию либо содержать допустимый автономный
установщик. Онлайн-bootstrapper не подходит для офлайн-установки. Этот путь
в данной версии не реализован и не проверен.

Необязательные [PowerShell-скрипты WSLg](../windows/README.ru.md) устанавливают
и запускают Linux-приложение в существующем Debian 13+ x86-64 под WSL2. Они
передают отдельные аргументы, проверяют дистрибутив/архитектуру, преобразуют путь
установщика и проверяют зависимости/namespaces. WSL не устанавливается;
нативное приложение Windows не создаётся. Скрытого автоматического перехода
нет. Скрипты не запускались на Windows: процессы, пути, графика, остановка,
диалоги и сквозной учебный путь остаются непроверенными. Linux-приложение
сохраняет собственную подготовку файлов и изоляцию.

## Конкретные непроверенные участки

Windows native и WSLg, ARM, macOS, старые glibc, все оконные менеджеры/portals,
системы с запрещёнными user namespaces, интеграция доступности со всеми
версиями WebView. Это области отсутствующей проверки, а не успешные результаты.

При обнаружении WSL настройки показывают `Linux / WSLg (unverified)`.
Это обозначение режима, а не заявление о проверке Windows.
