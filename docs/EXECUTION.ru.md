# Модель локального запуска и изоляции

[English](EXECUTION.md) · [Платформы](PLATFORMS.ru.md)

## Граница доступа

Rust получает снимок исходников через Tauri IPC и выполняет блокирующие операции
в рабочем потоке, отдельно от интерфейса. Аргументы передаются отдельными
строками `std::process::Command`. Код, имя проекта, stdin и пользовательские
пути не собираются в shell-команду.

В Linux каждый запуск компилятора и программы проходит через Bubblewrap.
Требуется `/usr/bin/bwrap`; если изоляция не создаётся, операция отклоняется.
Скрытого запуска без ограничений нет. Work и Learn используют одну границу.
Свободные проекты в этой реализации также не получают доступ к домашней папке
или сети.

Применяются `--unshare-all`, `--die-with-parent`, сброс capabilities и очистка
окружения. Создаются отдельные user/mount/PID/IPC/UTS/network namespaces.
Внутри видны:

| Путь | Доступ |
| --- | --- |
| `/usr`, существующие `/lib`, `/lib64`, `/bin` | Системные программы, заголовки и библиотеки только для чтения |
| `/etc/ld.so.cache`, если есть | Кэш загрузчика только для чтения |
| `/toolchain` | Компилятор и runtime только для чтения |
| `/work` | Рабочий временный каталог проекта/теста с записью |
| `/tmp` | Отдельная временная файловая система |
| `/proc`, `/dev` | Proc внутри namespace и минимальные синтетические устройства |

Домашняя папка, рабочие каталоги хоста, desktop sockets и сеть хоста не
подключаются. Сетевое namespace отдельно, маршрута в сеть хоста нет. Компилятору
передаётся только подготовленный снимок файлов. Файлы упражнения остаются
в его временном каталоге; сохранением проекта занимается доверенная нативная часть.

Это изоляция процессов ядром хоста, а не виртуальная машина. Системные файлы
в `/usr` доступны для чтения. Уязвимости ядра и вредоносный системный toolchain
не входят в гарантии. Доказательство полной безопасности не заявляется.

## Ресурсные лимиты

| Ограничение | Компиляция | Программа |
| --- | ---: | ---: |
| Реальное время | 30 секунд | По умолчанию 2 секунды; тесты задают ограниченные значения |
| Виртуальная память `RLIMIT_AS` | 768 MiB на процесс | 256 MiB на процесс |
| CPU `RLIMIT_CPU` | 25 секунд на процесс | 5 секунд на процесс |
| Задачи реального UID `RLIMIT_NPROC` | Исходное число + 128 | Исходное число + 128 |
| Открытые файлы `RLIMIT_NOFILE` | 128 на процесс | 128 на процесс |
| Размер файла `RLIMIT_FSIZE` | 8 MiB на файл | 8 MiB на файл |
| Суммарный stdout + stderr | По умолчанию 64 KiB на фазу | По умолчанию 64 KiB; тест может уменьшить |

Лимиты ресурсов не заменяют ограничение доступа к сети и файлам. Память и CPU
ограничены на процесс, а не суммарно через cgroup. Перед запуском подсчитываются задачи
пользователя; потолок равен этому числу + 128, но не выше унаследованного
жёсткого лимита. Это позволяет учитывать другие приложения пользователя.
`RLIMIT_NPROC` применяется
Linux к реальному пользователю и не является независимой точной квотой каждого
упражнения. Размер файла не ограничивает общий объём всех файлов. Лимит памяти
относится к адресному пространству, а не точному RSS.

stdout и stderr читаются параллельно в ограниченные буферы. Превышение времени,
вывода или Stop завершает PID 1 пространства имён, полученный через
`--info-fd` Bubblewrap. Ядро завершает всех потомков, включая создавших
собственные сессии. Приложение становится subreaper и дожидается конкретного
вспомогательного процесса после выхода supervisor, предотвращая накопление зомби.
Неуспешная компиляция или выполнение показывается как ошибка; падение программы
не завершает приложение.

## Подготовка файлов и тесты

Разрешены только относительные обычные компоненты пути. Абсолютные пути, `..`,
Windows-разделители и формы дисков, неподдерживаемые расширения отклоняются.
Снимок содержит 1–128 файлов `.kr`/`.krh`, всего до 4 MiB текста. Сборка идёт
в новом `TempDir`, а не в исходной папке пользователя. Явный корень Kremen
дополнительно удерживает import внутри снимка.

Каждый тест получает новый рабочий каталог и независимый stdin. Сравниваются
stdout, stderr, код выхода, необязательные созданные файлы и ожидаемые ошибки
компиляции согласно формату урока. Неудачная попытка не удаляет уже пройденный
урок. Воспроизводимость относится к заданным исходникам и вводу; произвольные
программы со временем, случайностью и зависимостью от планировщика не становятся
детерминированными. Локальные тесты открыты для просмотра и не защищают от
подглядывания.

Адаптер сохраняет оригинальный stderr. Только настоящая JSON-диагностика
frontend превращается в маркеры редактора. Сообщения C-backend и runtime могут
оставаться текстовыми. Сборка и исполнение — разные фазы с отдельными статусами
и лимитами. См. [аудит компилятора](COMPILER-AUDIT.ru.md).

## Windows

Вне Linux функция выполнения отклоняет операцию. Нативная Windows-изоляция
и встроенный процессный мост WSL не реализованы и не проверены. Необязательные
PowerShell-скрипты запускают целое Linux-приложение через WSLg; этот вариант
экспериментальный и на Windows-хосте не проверен. См.
[платформы](PLATFORMS.ru.md). Один Job Object или timeout не обеспечивает
описанные ограничения доступа к файлам и сети.
