# Формат уроков, версия 1

Учебное содержание хранится в `content/catalog.json` и `content/lessons/`
отдельно от React-компонентов. Каталог объявляет `schemaVersion: 1` и
`compilerVersion: "0.4.6"`; версия схемы также указана в каждом уроке.
Изменение смысла полей или правил проверки требует новой версии формата,
а не незаметной переинтерпретации старых материалов.

`scripts/sync-content.mjs` копирует каталог в `public/content/` для статического
интерфейса. Tauri отдельно включает тот же исходный каталог в нативные ресурсы
движка. Редактируйте `content/`, а не сгенерированную копию.

## Каталог и курс

Корневой объект содержит массивы `courses`, `lessons` и `roadmap`.
Идентификаторы курсов и уроков должны быть постоянными и уникальными:
сохранённый прогресс ссылается на ID уроков. `lessonIds` определяет их порядок.

Поля курса:

| Поле | Значение |
| --- | --- |
| `id` | Постоянный идентификатор курса. |
| `title`, `description` | Объекты со строками `en` и `ru`. |
| `art` | Локальная обложка, например `/art/foundations.svg`. |
| `lessonIds` | Упорядоченный список существующих ID уроков. |
| `duration` | Примерное общее время в минутах. |
| `level`, `prerequisites`, `outcomes` | Локализованные поясняющие строки. |

Элементы `roadmap` содержат `id`, локализованное `title`, `status: "planned"`,
предварительные темы и `sourceReference` с путём в `vendor/kremen/docs/`.
Это структура будущего содержания, а не законченные занятия. Текущий комплект
содержит 12 начальных уроков в шести курсах и семь запланированных модулей.

## Метаданные урока

Каждый законченный урок содержит:

| Поле | Значение |
| --- | --- |
| `id`, `schemaVersion`, `courseId` | Идентификатор, версия формата и курс. |
| `title`, `goal`, `description` | Локализованные название и цель. |
| `explanation`, `task` | Понятное объяснение и условие задачи на двух языках. |
| `duration` | Примерное время в минутах. |
| `markdown` | Пути `en`/`ru` относительно `content/`. |
| `solutionMarkdown` | Отдельные пути `en`/`ru` для решения и подсказок. |
| `example`, `starter`, `solution` | Полные строки исходного кода Kremen. |
| `files`, `entry` | Карта начальных относительных `.kr`/`.krh` файлов и точка входа. |
| `mode` | `learn` для упражнений; нативная проверка принудительно использует Learn. |
| `hints` | Отдельные последовательные массивы `en` и `ru`, открываемые по одному. |
| `walkthrough`, `transfer` | Разбор решения и связь идеи с другими языками. |
| `tests` | Один или несколько независимо запускаемых тестов. |

Основные Markdown-файлы содержат цель, объяснение, рабочий пример, задачу и
стартовый код. Отдельные файлы решения содержат последовательные подсказки,
разбор и перенос идеи; открытие урока не должно сразу раскрывать ответ.
У каждого урока четыре Markdown-файла: урок и решение по-английски и
по-русски. Примеры в Markdown должны совпадать с кодом в метаданных. Используйте настоящую
семантику закреплённой версии языка, включая результаты, ошибки ввода
и освобождение ресурсов.

Начальный код текущих упражнений — законченная компилируемая программа.
Успешная проверка компилятором ещё не означает решение задачи. Например,
стартовый код первого урока выводит одну строку, а решение должно вывести две.

## Тесты выполнения

Обычный тест выглядит так:

```json
{
  "id": "greeting",
  "name": {"en": "Two lines", "ru": "Две строки"},
  "stdin": "",
  "stdout": "Hello, Kremen!\nI can program.\n",
  "stderr": "",
  "exitCode": 0,
  "timeLimitMs": 2000,
  "outputLimitBytes": 65536,
  "files": []
}
```

Для каждого теста движок создаёт новый временный каталог, помещает в него
снимок отправленных исходников, компилирует с `--mode=learn` и передаёт stdin
запущенной программе. stdout, stderr и код завершения сравниваются точно.
Учитываются переводы строк, пробелы в конце и регистр. Вывод текстовый:
байты декодируются как UTF-8 с заменой некорректных последовательностей.
Результат показывает ожидаемое и фактическое значения. Файлы проверяются
до удаления рабочего каталога.

`timeLimitMs` ограничивает время выполнения отдельно от таймаута компилятора.
Нативный движок приводит значение к диапазону 100–10 000 мс.
`outputLimitBytes` — общий бюджет stdout и stderr, ограниченный диапазоном
1 024–262 144 байт. Другие ограничения описаны в
[модели запуска](EXECUTION.ru.md).

Файловая проверка задаёт относительный путь и точный текст UTF-8:

```json
"files": [{"path": "note.txt", "content": "saved\n"}]
```

Это проверка созданного программой файла, а не входной файл теста. Файл должен
быть обычным, не больше 1 МиБ для проверки и находиться внутри рабочего
каталога. Абсолютные пути, `..` и символические ссылки запрещены. Основной
формат — массив объектов `{path, content}`; текущий движок также принимает
словарь путь → содержимое для совместимости.

Задание на ошибку компиляции может вместо обычного результата указать:

```json
"expectedCompilationError": "E107"
```

Также принимается `{"code":"E107"}`. Нужны ненулевой результат компиляции
и настоящее сообщение Kremen с совпадающим кодом. Ошибка выполнения или
произвольный stderr не засчитываются. В первых 12 уроках такого задания нет;
поддержка движка и наличие готового учебного материала — отдельные вещи.

Успешное прохождение всех тестов при полной проверке позволяет сохранить
завершение урока. Запуск одного теста по `testId` не завершает весь урок.
Последующая ошибка не отменяет ранее сохранённый прогресс.

Тесты включены в локальное приложение с открытым кодом и доступны для чтения.
Они не являются секретными; защиты от списывания здесь нет.

## Подготовка и проверка материалов

1. Добавьте постоянные метаданные, оба перевода урока и решения и локальную обложку.
2. Объясните каждую новую конструкцию до того, как потребовать её в задаче.
3. Добавьте разные stdin там, где поведение зависит от ввода; различайте
   предметные коды `readIntResult` и системные errno.
4. Запустите `./scripts/build-toolchain.sh` и `npm run verify:lessons`.
5. Пройдите упражнение в установленном приложении, проверив изоляцию,
   диагностику, сравнение результата и сохранённое завершение.

Отдельная программа проверки вызывает настоящий закреплённый компилятор
и проверяет примеры, стартовый код, решения и файлы. Это инструмент автора
для доверенных материалов репозитория, а не песочница произвольных решений.
Нативная проверка упражнений использует слой изоляции приложения. Отчёт
записывается в `artifacts/lesson-validation.json`.
