# Как помочь Kremen Learn

[English](CONTRIBUTING.md)

Спасибо за помощь в создании понятной среды обучения программированию.
Сообщения об ошибках, улучшения объяснений, переводы, уроки и изменения кода
приветствуются. Issues и pull requests можно писать **на русском или английском**.

## Перед началом

Для небольшой правки можно сразу открыть pull request. Новую возможность или
крупное изменение лучше сначала обсудить в issue. Опишите проблему, которую
хотите решить, и приведите конкретный пример.

Перед сообщением о проблеме платформы посмотрите
[состояние платформ](docs/PLATFORMS.ru.md) и
[известные ограничения](docs/VERIFICATION.ru.md). Поддержка Windows не завершена;
уточняйте, относится ли сообщение к нативной Windows или экспериментальному
запуску через WSLg.

## Подготовка и проверка

Системные зависимости, закреплённая версия Rust и Node.js описаны в
[инструкции разработки](docs/DEVELOPMENT.ru.md). Из корня репозитория:

```sh
npm ci
sh scripts/build-toolchain.sh
npm run build
npm run desktop
```

Запустите проверки, которые относятся к вашим изменениям:

| Изменение | Проверка |
| --- | --- |
| Текст уроков, примеры или тесты | `python3 scripts/verify-lessons.py` |
| Rust, интеграция компилятора, хранение или процессы | `cargo test --manifest-path src-tauri/Cargo.toml --lib -- --include-ignored --test-threads=1` |
| Интерфейс | `npm run build`, затем `node scripts/verify-ui.mjs` при наличии Chromium |
| Установщик | `python3 installer/test_installer.py` |

Для полного набора нативных тестов нужны работающие Bubblewrap и пользовательские
пространства имён. Если проверка недоступна, укажите какая и почему; пропущенный
тест не считается пройденным. Браузерный предпросмотр не компилирует программы
и не сохраняет файлы через нативную часть. Эти действия проверяйте в настольном
приложении.

## Подготовка pull request

- Посвятите изменение одной проблеме. Объясните, что изменится для учащегося
  и как это проверено. Для видимых изменений приложите скриншоты.
- Согласуйте русский и английский интерфейс, содержание уроков и соответствующую
  документацию. См. [формат уроков](docs/LESSON-FORMAT.ru.md).
- Сохраняйте исходные сообщения компилятора и реальные результаты команд.
  Не заменяйте ошибку запуска или недоступность изоляции имитацией успеха.
- Сохраняйте закреплённую версию компилятора. Изменения языка объясняйте отдельно;
  не обновляйте включённые исходники попутно с правкой интерфейса.
- Следуйте стилю соседнего кода. Для Rust используйте `cargo fmt --manifest-path
  src-tauri/Cargo.toml`, для изменённых файлов интерфейса — существующий стиль
  Prettier.
- Не включайте в коммиты кэши сборки, личные проекты, базы данных и готовые
  установщики. Не публикуйте учётные данные и закрытый код в сообщениях.

Изменения распространяются под [лицензией MIT](LICENSE) проекта.
Сохраняйте лицензии и сведения об авторах добавляемых сторонних материалов.
